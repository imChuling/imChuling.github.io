# As You Read：操作与实现思路

这件作品的出发点是：不要求访客先学习一套音乐工具的规则，而是让人先阅读、移动、聆听，在感知中发现规则。浏览不是触发一段配乐，而是在改变正在发生的声音。回到同一个位置时，声音保留一点经过的痕迹。

目前是独立试听页 `as-you-read.html`，主页还没有自动播放声音。先把这一页的体验做稳，再接到主页，是为了避免招生官阅读作品时受到未经验证的声音干扰。

## 你现在怎么使用

1. 打开本地网站的 `http://127.0.0.1:8765/as-you-read.html`。
2. 点击“选择一段声音”，选一段自己的吉他、键盘或环境录音。WAV 是最方便的排查格式。选入的文件只在浏览器本机解码，没有上传接口。
3. 点击“开启声音”，从较低音量开始。进入第二段，再回到第一段。
4. 用“对照初始声音”比较处理前后的差别；它暂时去掉颗粒混合，保留统一的输出衰减，所以不是原文件的原始响度。
5. “从头播放”从录音开头重新开始；“重新开始”清除浏览记忆。后者不会重建 RNBO，因此不保证清空效果器内部的延迟尾音。

网页试听不需要 Max 一直开着，也不需要 WebSocket、本地音频服务器或 Python 声音合成脚本。浏览器本身运行导出的 RNBO 音频引擎。本地 HTTP 服务只负责提供页面文件。

## 声音是怎样来的

```text
本地录音 → 浏览器解码与循环播放 → Max/RNBO 导出的音频处理 → 音量 → 扬声器
                                 ↑
                     网页滚动、章节位置、是否回返
```

Max 是声音处理的创作环境，RNBO 把其中的处理图导出为浏览器可以执行的代码。JavaScript 负责网页事件、播放和参数控制，不重新编写颗粒算法。Python 只用来整理 Max 的 JSON 工程和检查连线，不生成网页听到的音乐。

复用的核心是 szkkng 的 JR-Granular（GPL-3.0）。它把输入声音切成短小片段，改变片段的位置、长度、间隔与音高。我们改变的是它的使用场景和控制方式。

已经搭好的另一条处理链是 JR-Granular → Overdrive → Plate Reverb。后两者来自 Manuel Poletti / Cycling ’74 的 RNBO Guitar Pedals（MIT）。颗粒负责模糊轮廓，过载增加粗粝感，混响延长声音留下的空间。声源本身仍很重要：持续的吉他和弦与短促的人声录音会产生完全不同的结果。

## 浏览怎样变成音乐

| 行为 | 听觉意图 | 颗粒混合 | 颗粒长度 | 触发间隔 | 音高 |
| --- | --- | ---: | ---: | ---: | ---: |
| 初次阅读 | 还能认出录音的轮廓 | 35 | 180 ms | 100 ms | 0 |
| 经过第二段 | 声音更稠密、展开 | 85 | 360 ms | 45 ms | −5 半音 |
| 回到第一段 | 留下一部分经过的影响 | 65 | 300 ms | 65 ms | 0 |
| 原声对照 | 暂时退去颗粒层 | 0 | — | — | — |

滚动速度只轻微增加颗粒混合、缩短间隔；停下后逐渐恢复。参数做平滑过渡，避免每一次滚轮事件都变成突兀的开关。现阶段“记忆”是浏览状态，不是录音回放，也不是用户行为模型或 AI。

这让规则足够容易被耳朵发现：向下走，声音变浓；回头看，熟悉的内容带着余留。无需额外键盘操作、打分或教程。

## 我怎么搭建和排查

1. 先保留可回滚的 Git 版本，并把原型放在独立页面。
2. 查找可复用、授权明确的开源声音处理，保存原始补丁与许可证。
3. 读取 `.maxpat` 的 JSON，把原有 DSP 放到独立子补丁，连接输入与输出；不把上游的颗粒、失真、混响算法重新写一遍。
4. 在 Max 内打开并编译，通过 RNBO Web Export 导出。仅仅工程文件可以解析、连线存在，不代表 Max 编译或导出成功。
5. 用 RNBO 1.3.5 浏览器运行库加载导出，在网页上把三种浏览状态映射到参数。
6. 实际检查文件能解码、输出存在非零信号、35 → 85 → 65 的参数变化、原声对照、重置和暂停。数值通过只说明音频链在运行，不等于已经完成主观音色审美判断。
7. 保留失败实验的记录，但把它们从日常使用目录移开，不让你面对一堆用途不明的窗口。

排查中发现自动导出使用了错误配置名：Web Export 的字段应为 `file_name`，不是 `export_name`。修正这一点不自动意味着整个组合导出已成功，仍需确认输出文件及浏览器运行结果。

## 本轮验证结果

颗粒引擎在浏览器中重新验证通过，实测输出峰值约 0.058（数字幅度），播放、暂停和重置均可执行；当前预设映射测试 2 项通过。加载期间禁止重复选文件，初始化失败会释放音频上下文，重置时会同步清除滚动强度。

## 怎样继续修改而不越做越复杂

只改声音氛围时，优先调整 `rnbo-engine.mjs` 的三组参数；不用重新搭网页。只有更换音频算法或改变 Max 内部连线，才需要重新导出。导出完成后先验证，再替换网页的 `scene.export.json`，保留对应许可证。

最终作品需要一段授权明确、能代表你的默认声源，这样访客点击即可聆听，不必自行选文件。当前“本地选音频”是试听入口，不应被当成最终招生官体验。你自己的短吉他和弦或键盘音色适合成为这一层素材；这里尚未把任何私人录音发布到网站。

公开前保留源代码及 GPL/MIT 授权说明，并把你的贡献准确表述为“基于开源 DSP 的浏览行为映射、交互设计与声音设计”。整个作品的独特性来自这套感知与浏览的关系，不需要声称底层颗粒算法由自己发明，也不声称没有任何人做过类似交互。
